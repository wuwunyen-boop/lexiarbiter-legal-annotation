# LexiArbiter 法律文件標註工具

LexiArbiter 是以 Python 和 PySide6 製作的桌面標註程式。主要提供法律文件的專業術語標註、文件概念及上下位階層管理、逐筆解釋編輯，以及標註進度儲存與模型文字匯出。

## 功能總覽

- 讀取 Word 文件、司法開放資料 JSON、LexiArbiter `.lexa` 進度檔，以及舊格式模型 `.txt`。
- 以滑鼠選取文字後標注「專業術語」，可連結既有概念或新增概念。
- 可自動標注文件中相同的完整術語；較長術語可取代其範圍內較短的同群組標注，衝突範圍會略過。
- 以樹狀清單管理文件概念、上位概念與下位概念；可新增、編輯及刪除概念。
- 逐筆檢視或編輯同一概念的術語出現位置與解釋，也可一次編輯勾選的多筆解釋。
- 點選右側概念會跳到文件中的第一筆術語，並反白該概念的所有出現位置。
- 點選文件中的已標注詞可查看狀態列資訊；滑鼠停留會顯示術語、概念、上位概念及解釋提示。點到未標注文字時會清除先前的概念反白。
- 概念底色依階層呈現：第一、二階使用不同概念色，第三階起沿用第二階祖先色並降低不透明度；第一階標注另有框線。
- 支援復原、重做、自動存檔、異常時緊急備份與操作記錄。

## 環境需求與安裝

- Python 3.10 或更新版本
- PySide6 6.5 以上、7.0 以下
- python-docx 1.1.0 或更新版本

在 Windows PowerShell 或 VS Code 終端機中切換到專案根目錄（可看到 `main.py` 和 `requirements.txt`），執行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 啟動程式

```powershell
.\.venv\Scripts\python.exe main.py
```

程式會載入 `configs/annotation_modes/` 中的標註模式，並讀取 `configs/user_preferences.json` 的使用者設定。若尚未設定偏好，程式會使用內建預設值。

## 基本標注流程

1. 選擇「檔案 → 開啟檔案」，載入 `.docx`、司法 `.json`、`.lexa` 或舊格式 `.txt`；也可以用「開啟資料夾」瀏覽右側檔案清單。
2. 在「標註模式」選擇「術語與解釋標註（概念連結）」。
3. 在文件中以滑鼠拖曳選取完整術語。預設會在選取處顯示快速標注選單；也可在選取範圍按右鍵，選第一層的「專業術語」。
4. 在概念對話框選取既有概念，或輸入新概念名稱後按「確定」。新概念會顯示在右側概念樹。
5. 若開啟相同詞語自動標注，程式會搜尋相同術語並建立連結到相同概念的標注。請核對自動標注結果及文字範圍。
6. 按 `Ctrl+S` 儲存 `.lexa` 進度；完成後可用「檔案 → 匯出模型用 .txt」輸出模型資料。

同一文件概念的不同出現位置應選擇相同的既有概念，讓它們共用 `concept_id`。標注範圍應精確包含術語文字，不要包含前後空白或標點。

## 概念與解釋

- 右側「文件概念清單」以階層樹顯示概念。點概念會跳到第一筆標注並反白全部同概念的出現位置；第一筆使用系統文字選取色，其他位置以黃色標示。
- 單擊文件中的已標注術語會將其設為目前操作目標，並展開、選中右側對應概念。單擊未標注文字會清除概念反白。
- 右鍵點選取文字或已標注術語，可直接選「專業術語」；點到已連結概念的術語時，也可選「編輯概念…」。右鍵點在目前反白範圍內會保留選取範圍。
- 右鍵點右側概念列，可編輯概念名稱、上位概念及解釋，或刪除概念。刪除概念會解除其術語連結，並將下位概念移到原上位概念。
- 設定上位概念時，先選要設定的既有概念，再選既有上位概念或輸入新上位概念。最上層概念以「上位概念等於自己」表示；不可留空或建立「無」、「沒有」等假概念。
- 編輯概念視窗會列出該概念的術語出現位置及前後文。可勾選個別筆數或全選，並輸入解釋；儲存後只更新勾選的筆數，未勾選筆數保留原解釋。
- 滑鼠停留在術語或解釋範圍上會顯示相關提示；狀態列也會顯示目前術語、概念、上位概念及解釋摘要。

## 檔案格式與匯出

| 格式 | 用途 |
| --- | --- |
| `.docx` | 讀取 Word 段落、表格及可取得的註腳文字；轉成純文字供標注，原有版面樣式不保留。 |
| `.json` | 讀取司法開放資料的 `JFULL` 文字；常見的 `<br>` 換行會轉成真正換行。 |
| `.lexa` | LexiArbiter 標注進度，包含原文、概念、階層、標注範圍、標籤與逐筆解釋，可繼續編輯。 |
| `.txt` | 匯出供模型使用的 `<P>標籤=概念名稱|文字</P>` 格式；也可載入相容的舊格式文字進行檢查或重新匯出，並由標籤還原概念名稱。 |

匯出會提示輸出段數、未涵蓋字元及標籤群組不完整的段落。若標注發生同一群組衝突，程式會提示範圍；應先清理衝突再匯出。

模型 `.txt` 不包含概念上下位階層或逐筆解釋；需要保留完整編輯資料時請儲存 `.lexa`。

`.lexa` 會保存概念名稱及概念關係，標注透過 `concept_id` 連結概念、透過 `broader_concept_id` 指向上位概念。概念 ID 是程式產生的識別碼，與範例檔中的 ID 不同屬正常情況；檢查資料時應確認 ID 指向的名稱及階層關係正確。

## 復原、重做與快捷鍵

| 快捷鍵 | 功能 |
| --- | --- |
| `Ctrl+O` | 開啟檔案 |
| `Ctrl+Shift+O` | 開啟資料夾 |
| `Ctrl+S` | 儲存 `.lexa` 進度 |
| `Ctrl+E` | 匯出模型 `.txt` |
| `Ctrl+Z` | 復原 |
| `Ctrl+Y` 或 `Ctrl+Shift+Z` | 重做 |
| `Ctrl+D` | 刪除游標處標注 |
| `Ctrl+C` | 複製選取文字 |
| `Alt+Up` / `Alt+Down` | 開啟右側清單中的上一個／下一個檔案 |

標籤快捷鍵依標註模式設定，也可在 `configs/user_preferences.json` 覆寫。標注和概念修改會加入復原紀錄；刪除後可以復原。

## 自動存檔與診斷

- 文件有未儲存變更時，程式每分鐘建立一次 autosave；開啟原檔時若有較新的 autosave，會詢問是否還原。
- 正式儲存成功後會清理對應 autosave；程式發生未處理錯誤時會嘗試建立緊急備份。
- 「說明」選單可開啟 log 資料夾或複製診斷資訊。回報問題時請提供 `logs/lexiarbiter.log`。

## 測試與驗證

執行內建測試：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

測試判決文件、標註進度檔、autosave 與 crash backup 可能含有法律文本或標註資料，請留在本機；這些資料已列入 `.gitignore`，不會上傳到 GitHub。
